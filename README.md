# 엄마 이게뭐야

### 아이가 카메라로 물건을 비추면, AI가 설명하고 말해주는 앱

카메라에 비친 물건을 **YOLOv8**으로 탐지해, **5살 아이가 이해할 수 있는 말로 설명**하고 **음성으로 읽어줍니다.** 아이가 무엇에 관심을 가졌는지 기록해 부모에게 리포트로 보내고, **손가락 제스처로 조작하는 단어 맞추기 게임**을 함께 제공합니다.

| 항목 | 내용 |
|---|---|
| **유형** | 팀 프로젝트 (메타버스 아카데미 2기) · AI 개발자 5명 |
| **기간** | 2023.08 ~ 2023.09 (1개월) |
| **발주처** | 한국전파진흥협회 |
| **데이터** | **94개 클래스 · 5,576장 직접 라벨링** · 증강 후 약 3배 |
| **담당** | 데이터 수집 · 이미지 라벨링 · YOLOv8 커스텀 학습 · 손가락 제스처 인식 · 음성 출력 · Flask 백엔드 |

## 1. 무엇을 만들었나

아이가 "엄마 이게 뭐야?"라고 묻는 상황을 앱이 대신 받아주는 것이 출발점입니다.

```
아이가 물건을 카메라에 비춤
   │
   ├─ ① YOLOv8 탐지 ──→ 가장 확신도 높은 물건 1개 선택 (person 제외)
   │
   ├─ ② GPT 설명 생성 ─→ "5살 아이가 이해할 수 있게 2줄 이내, 반말로"
   │
   ├─ ③ gTTS 음성 합성 → 한국어 mp3 로 읽어줌
   │
   └─ ④ SQLite 기록 ──→ 날짜별 관심 물건 통계 → 부모에게 이메일 리포트
```

여기에 **카메라만으로 조작하는 단어 맞추기 게임**을 붙였습니다. 글을 모르는 아이도 화면을 만지지 않고 손가락만으로 놀 수 있게 하기 위해서입니다.

기획 의도는 **"아이의 호기심을 해결해 주면서, 부모가 자녀의 관심사를 손쉽게 알 수 있는 서비스"** 였고, 세 가지 기능으로 나눴습니다.

| 기능 | 내용 |
|---|---|
| **① 뭐든 물어봐** | 물건을 비추면 탐지 → 설명 → 음성으로 읽어줌 |
| **② 아이의 관심사 알림** | 탐지 기록을 쌓아 날짜별 차트 + 부모 이메일 리포트 |
| **③ 단어 학습** | 손가락 제스처로 조작하는 단어 맞추기 게임 |

### 화면 구성

| 라우트 | 화면 |
|---|---|
| `/` | 인트로 |
| `/obdetect` | 물건 탐지 — 카메라 → 탐지 결과 이미지 + 설명 + 음성 |
| `/quiz` | 손가락 제스처 단어 게임 |
| `/result_chart` | 날짜별 관심 물건 차트 |
| `/result` | 부모 이메일로 「우리 애의 관심물건 TOP 5」 발송 |

## 2. 핵심 문제 — 클래스 불균형

### 데이터를 직접 만들었습니다

집 안 물건 중심으로 **94개 클래스, 5,576장**을 직접 수집하고 라벨링했습니다. 의자·마우스·이어폰 같은 일반 사물부터 프라이팬·가스레인지·고무장갑처럼 공개 데이터셋에 잘 없는 생활용품까지 포함했습니다.

### 문제 발견

사전학습된 YOLOv8이 이미 알고 있는 일반 객체 외에 **서비스에 필요한 물건을 커스텀 클래스로 추가**해야 했습니다. 학습 결과를 확인하다가 **커스텀 클래스의 탐지율이 유독 낮다**는 것을 발견했습니다.

원인을 따라가 보니 학습 데이터의 구성 자체가 기울어져 있었습니다.

- **기존 사전학습 클래스** — 대규모 공개 데이터셋으로 이미 충분한 샘플을 가진 상태
- **새로 추가한 커스텀 클래스** — 직접 수집·라벨링한 소량의 이미지

> ⚠️ 클래스 간 샘플 수 격차가 크면 모델은 **다수 클래스로 예측을 몰아버리는 것이 손실을 줄이는 데 유리**하다고 학습합니다.
> 커스텀 클래스를 아예 예측하지 않는 방향으로 수렴하는 것이 이 문제의 본질이었습니다.

### 해결 — 세 가지

| # | 조치 | 내용 |
|---|---|---|
| 1 | **데이터 증강** | Rotation · Cutout 등으로 **약 3배** 확보 |
| 2 | **클래스별 샘플 수 조정** | 데이터셋 구성 단계에서 클래스 간 비율 격차를 줄임 |
| 3 | **오라벨 수정** | 학습 데이터를 다시 훑어 **잘못 라벨링된 것을 찾아 고침** |

3번이 의외로 효과가 컸습니다. **5,576장을 사람이 나눠 라벨링하다 보니 기준이 흔들린 구간이 있었고**, 모델이 못 맞히는 클래스를 따라가 보면 데이터 쪽에 원인이 있는 경우가 많았습니다. **"모델이 틀렸다"보다 "라벨이 틀렸다"를 먼저 의심하게 된 계기**입니다.

### 지금 돌아보면 — 이 프로젝트의 가장 아쉬운 점

당시에는 개선 여부를 주로 **육안 확인과 탐지 성공 여부**로 판단했고, **클래스별 precision/recall과 mAP를 before/after로 기록해두지 않았습니다.**

이 아쉬움이 이후 작업 방식을 바꿨습니다. [Emour](https://github.com/chlgks2/Emour)에서는 처음부터 **macro-F1을 기준 지표로 정하고 best epoch를 선택**했으며, 클래스 불균형에는 가중 손실을 적용했고, 나아가 **모델 간 비교 시 평가 데이터 누수가 있으면 점수가 뒤집힌다는 것까지 잡아내** 누수 없는 비교 기준을 확립했습니다.

**"무엇으로 좋아졌다고 말할 것인가"를 먼저 정하는 습관은, 이 프로젝트에서 그것이 없어 겪은 불편에서 나왔습니다.**

## 3. 손가락 제스처 인식 — 좋은 특징이 모델을 단순하게 만든다

글을 모르는 아이가 화면을 만지지 않고 조작할 수 있어야 했습니다. MediaPipe의 손 랜드마크를 그대로 쓰지 않고, **각도 특징을 뽑아 KNN으로 분류**했습니다.

```
MediaPipe Hands
   → 21개 랜드마크 (x, y, z)
   → 뼈대 벡터 20개 (v2 - v1) → L2 정규화        ← 손 크기·거리에 불변
   → 인접 벡터 사이 각도 15개 (arccos of dot)     ← 회전에 불변
   → KNN (k=5, finger_recognition.csv 로 학습)
   → 제스처 0~5  { nothing, point, v, three, four, five }
```

**왜 좌표가 아니라 각도인가** — 랜드마크 좌표를 그대로 쓰면 손이 카메라에 가까울 때와 멀 때, 화면 어디에 있느냐에 따라 값이 전부 달라집니다. **뼈대 벡터를 정규화하고 그 사이 각도만 남기면 손의 크기·위치·거리와 무관한 특징**이 됩니다. 이 표현 위에서는 KNN 하나로 충분했습니다.

### 게임 규칙

| 동작 | 제스처 | 처리 |
|---|---|---|
| 게임 시작 | ✌️ `v` 를 **3초 유지** | 카운트다운 후 시작 |
| 정답 선택 | ☝️ `point` 로 단어를 가리킴 | 검지 끝 좌표가 단어 박스 안에 들어오면 판정 |
| 정답 | | ⭕ 표시 + `circle.mp3` + 점수 +1 → 다음 문제 |
| 오답 | | ❌ 표시 + `x.mp3` |
| 종료 | 20초 경과 | `end.mp3` + 점수 초기화 |

화면에는 아이용 단어 30개 중 5개를 무작위로 배치하고, 정답 단어의 **그림**을 우측 상단에 보여줍니다. 한글은 OpenCV가 그리지 못해 **PIL로 렌더링한 뒤 배열로 되돌리는 방식**(`myPutText`)으로 처리했고, 캐릭터 오버레이는 알파 채널을 직접 블렌딩했습니다.

## 4. Flask 연동 — 학습에서 끝내지 않기

학습한 모델을 Flask 백엔드에 올려 추론 결과를 API로 내려주는 구조를 구성했습니다.

```python
@bp.route('/detect', methods=['POST'])
def detect():
    image = cv2.imdecode(np.frombuffer(base64.b64decode(data['image']), np.uint8), cv2.IMREAD_COLOR)
    results = model.predict(source=image, save=True, conf=0.25)

    # person 을 제외하고 확신도가 가장 높은 객체 1개만 고른다
    # → 아이에게는 "여러 개"가 아니라 "지금 보고 있는 그것" 하나를 말해줘야 한다
    ...
    explanation = f"이것은 '{label}'야. " + get_gpt_response(label)
    save_to_db(label, now)
    return jsonify({"explanation": explanation, "image": image_base64,
                    "audio_path": generate_audio_from_text(explanation)})
```

탐지 기록은 SQLite에 `(label, time_information)`으로 쌓이고, `/chart_data/<date>`가 날짜별 빈도를 집계해 차트로 보여줍니다. `/result`는 누적 상위 5개를 뽑아 **부모 이메일로 발송**합니다.

> **모델 학습에서 끝내지 않고 서비스에 연결해봐야 실제 문제가 보인다**는 것을 처음 체감한 프로젝트입니다.
> 노트북에서 잘 돌던 추론이 실시간 요청에서는 다르게 동작하고, **학습 시 전처리와 서빙 시 전처리를 일치시켜야 한다**는 것도 이때 알았습니다.
> 이 감각은 이후 Emour에서 **추론·학습·백엔드 전송 형식을 완전히 일치시키고, AI 서버와의 계약(스키마·라벨)을 고정**하는 설계로 이어졌습니다.

## 7. 알려진 한계

당시 구현의 한계를 그대로 기록합니다.

| 한계 | 내용 |
|---|---|
| **성능 지표 부재** | 클래스 불균형 개선을 육안으로만 확인했고 mAP·precision/recall을 before/after로 남기지 않았습니다 |
| 탐지 결과 이미지 경로가 절대경로 | `model.predict(save=True)`가 만든 `runs/detect/predict*` 폴더를 파일시스템에서 직접 찾아 읽습니다. 예측 결과를 메모리에서 바로 인코딩하는 편이 맞습니다 |
| 게임 상태가 프레임 생성 함수의 지역 변수 | 동시 접속 시 세션 분리가 되지 않습니다 |
| 웹캠을 서버가 직접 연다 | `cv2.VideoCapture(0)`이 서버 측 카메라를 잡으므로 로컬 실행 전용입니다 |
| `text-davinci-003` 단종 | 현재는 사용할 수 없어 최신 모델로 교체가 필요합니다 |

### 발표 당시 정리한 상용화 과제

1. **데이터 불균형** — 기존 YOLOv8 클래스와 새로 추가한 커스텀 클래스 사이의 격차
2. **TTS 개선** — 기계음 대신 아이가 좋아하는 캐릭터 목소리, 다국어 지원
3. **앱 출시** — 언어 선택(한국어/English/日本語/中文/Français) · 음성 선택

## 8. 배운 점

- **데이터 문제는 모델을 바꿔서 해결되지 않습니다.** 탐지율이 낮은 원인이 모델이 아니라 데이터 구성에 있다는 것을 확인한 첫 경험이었습니다. 증강·비율 조정·오라벨 수정 셋 다 데이터 쪽 조치였습니다.
- **개선을 주장하려면 지표가 먼저 있어야 합니다.** 이 프로젝트에 지표가 없었던 것이 이후 평가 체계를 먼저 설계하는 습관으로 이어졌습니다.
- **좋은 특징 설계는 모델을 단순하게 만듭니다.** 손 제스처는 좌표를 각도로 바꾼 것만으로 KNN 하나면 충분했습니다.
- 객체 탐지 학습 파이프라인(수집 → 라벨링 → 학습 → 서빙)의 전 구간을 이해했습니다.
